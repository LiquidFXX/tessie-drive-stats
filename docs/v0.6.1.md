# v0.6.1 — Analytics device organization

Version 0.6.1 reorganizes Tessie Drive Stats entities into multiple Home Assistant devices so installations with hundreds of entities are easier to browse.

This release does **not** change the underlying entity unique IDs, sensor calculations, Tessie API calls, or historical storage format.

## Device layout

For a Tessie vehicle named `My Tesla`, Home Assistant will show:

- `My Tesla` — live vehicle state, odometer, connection, current battery/range, and current cabin/outside temperature
- `My Tesla · Driving` — drive totals and Last Drive data
- `My Tesla · Efficiency` — v0.5 Efficiency Intelligence and the unusual-efficiency binary sensor
- `My Tesla · Charging` — charging state, charge sessions, Supercharging, charging costs, and fleet invoice diagnostics
- `My Tesla · Charging Economics` — v0.6 charging-efficiency and cost-per-mile analytics
- `My Tesla · Battery` — consumption-since-charge, battery telemetry, health, capacity, degradation, and pack-temperature data
- `My Tesla · Idle & Vampire` — idle, Sentry, climate-idle, and Last Idle analytics
- `My Tesla · Lifetime` — vehicle-lifetime counters and Tessie recorded-lifetime history
- `My Tesla · Tires & Alerts` — tire pressures, tire warnings, and firmware alerts
- `My Tesla · Navigation & Software` — navigation, software-update, and observed activity diagnostics

The analytics devices are linked to the main vehicle through Home Assistant's `via_device` relationship.

## Entity-ID compatibility

Existing entity registry entries keep their current entity IDs because v0.6.1 does not change the integration's VIN-based unique IDs.

For new installations, Tessie Drive Stats also supplies a suggested object ID based on the Tessie vehicle name and the stable sensor key. This prevents the analytics-device suffix (for example `· Driving`) from becoming part of newly-created entity IDs.

Moving an entity between Home Assistant devices does not require dashboard or automation changes when the existing entity ID is already registered.

## Why devices instead of entity categories?

Home Assistant's entity categories are intended for configuration and diagnostic entities. Tessie Drive Stats therefore keeps using those categories only where they are semantically appropriate and uses separate devices for functional analytics groups such as Driving, Charging, Battery, and Lifetime.

## Upgrade notes

After updating to v0.6.1, restart Home Assistant. The device registry will create the analytics devices and associate existing Tessie Drive Stats entities with their new groups.

The number of entities is unchanged from v0.6.0: **311 sensors plus 5 problem/warning binary sensors**.
